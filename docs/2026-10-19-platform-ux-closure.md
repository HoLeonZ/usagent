## 一、平台现在提供什么（按"你要做什么"列）

| 你想做的事 | 入口 |

## 二、这一轮改了什么（按类别，附提交）

- **指示器说假话一族**（`8791b0c`）：失败任务的真实原因到不了界面（判据 `st.error` 太宽）；
  终态不写回 live region；「任务丢失」是半吊子终态；排队中假装在取链路；在途任务刷新后找不回来
  （新增 `GET /api/jobs` + 加载时恢复）；「回测」按钮的守卫其实是个 1.5 秒定时器。
- **a11y 一族**（`8791b0c`、`90c368e`）：`--acc` 只被引用从未定义（焦点环整条作废）；裸 `<a>`
  落到 UA 默认蓝；`#lf` 等控件没有可访问名；一个动作两个 Tab 停靠点；列头命中区 7×19px；
  判词格缺 live region；锚点被常驻顶栏/粘性目录吃掉（**量**出来的，不是猜的）。
- **口径与标签**（`f85ea90`）：超额的单位（pp 而非 %）；19 个指标没有定义；`n_trials` 一词两数；
  k 的释义差 1；族的机制行把「族」印两遍且带 markdown 星号；「全窗」右端写死会静默丢最后几天；
  横幅"标红几张卡"与实际不符；死链；参数列对 CLI 产物的断言是猜的。
- **陈旧读数与细节**（`3e05152`）：没有独立刷新入口、跑完不刷卡片读数；`jsteps` 每 900ms 整块
  重写（焦点每秒被销毁）；筛选空态无解释；族的固定轴没渲染；窗口下限（< 5 个交易日当场拒）；
  产物写不进去时的裸异常。
- **静默失真（核心指标与接口）**（`bbc72bd`、`cb09dad`、`d236ddf`）：
  ①**曝光匹配超额**在窗口伸到池子覆盖之外时，两条腿在不同跨度上比较（把"池子没有数据"当成
  "那天没涨"）⇒ 一个什么都不做的窗口会报出可观的"超额"；现在两条腿显式裁到 `[lo, hi)` 与
  共同覆盖的日子上，并把"只比了一部分"披露到面板；**正常窗口逐位不变**（7 个真数据 golden
  基线未动）。
  ②接口 JSON 里的裸 `NaN`（Python 会写、JS 的 `JSON.parse` 会拒）⇒ **整次运行的结果渲染不出来**，
  且前端把它误报成"读不到任务状态"；现在唯一出口处统一净化成 `null`。
  ③台账里的坏行被**静默跳过** ⇒ 少记一次试验 ⇒ k 偏小；现在跳过但计数并警告。
- **半拉子修复与我自己引入的回归**（`d587831`、`d4c8490`、`7d3f576`、`2204368`、`1e37360`）：
  报告的 50 条截断"接口发了页面没显示"；报告参数列对不在台账里的运行仍说"在定义体里"；
  报告被清理后链接给人看的是一坨 JSON；台账第 31 条只能去 CSV 看（新增可视「载入全部」）；
  以及一个 **blocking 回归**：`cliCmd()` 里 `const fp = pr ? …` 写在 `const pr = …` 之前（TDZ）
  ⇒ 面板建不出来 ⇒ 整条回测流程是死的。
- **权威 holdout 台账上页面**（`ff8e50e`）：claim 与 lock 分开数、规范窗口是否被 claim 过、
  平台越界运行里登记进这本账的条数；两本账的区别可悬停查看。
- **候选生命周期的第一步也上按钮**（第五个"做一次真迭代"才撞出来的洞）：此前第一步是手工的 ——
  拷定义体、改 `NAME`（注册表校验"必须与文件名一致"）、`n_comparisons` +1、声明 `derived_from`、
  换掉继承来的 `VERDICT`。**四种错法没有一种会当场报错**（判词抄错 → 报告与判词互相矛盾；
  `derived_from` 漏写 → DSR 分母偏小、判词偏乐观），所以不靠"记得"，靠平台替人填好：
  preset 卡上新增「复制成新候选」→ `GET /api/candidate_skeleton/<id>` → 建议路径 + 可直接落盘的正文。
  两条细节：文件名**避让已存在的**（`_cand` → `_cand2`…，第二次点同一张卡不会建议覆盖第一条候选）；
  平台**只生成不写盘**（存与改是开发者的决定）。
  验证：对**全部 6 条** preset 生成的文本都真的 `exec` 过并走注册表自己的 `validate()`（不是字符串断言）；
  浏览器里实测 6 张 preset 卡各一个按钮、15 张族卡没有（族没有这几样要改的东西），任何宽度都无横向溢出。
- **判据④ 的读数上面板**（同一轮里顺手撞出来的第二个洞）：运气对照（同止损止盈、同笔数、同机会集
  随机入场 200 次）平台**能跑**，但它的读数（落在第几百分位）只写进报告摘要，面板上只有"跑过 200 次"
  这句**计数** —— 而判词是在面板上写的，写的时候手上没有那个数，就只能抄别的候选的。现在：
  ① 读数进 `metrics` 与**台账**（新增 `ctl_pct` / `ctl_failed` 两列），面板多一格「随机入场百分位」；
  ② 对比视图多一行，且**只有一边跑了对照时明说那行没有可比值**（勾选框默认不跑 ⇒ 这是常态）；
  ③ 「复制 VERDICT 草稿」把它一起写进判词，并**连口径一起写**：面板给的是**整窗一个数**，
  判据④要的是**逐折** ≥3/4 折在随机分布中位以上（那是 `family_search` / `wfv_search` 的逐折输出）。
  这条口径差是**真的存在**的，不是措辞洁癖 —— 拿整窗百分位去声称"过了判据④"就是错。
  顺带补了一条护栏：`METRIC_HELP` 的 tooltip 走 `title="${esc(...)}"`，所以里面**不能有标签**
  （`esc` 会把 `<b>` 变成解析后的字面 `<b>`，悬停框里显示这几个字符本身）。我第一版就写了 `<b>`。
- **「交付一条候选前」上代码地图**（同一轮里顺手撞出来的第三个洞，是前两个的反面：
  不是数字没入口，而是**规矩没入口**）：四条判据此前只写在**定义体的 docstring** 里，
  页面上有 `validated` / `delivered` 的字样，但从没有一处说清四条判据**是什么**、
  以及**这一页能答到哪一条**。现在地图里给出四条（不抄任何观测数字，§7）、
  **判给谁看**（族走 `family_search --run`；WFV 网格选出的及其参数兄弟走 `wfv_search --run`）、
  基准线是哪一条（`us_uptrend_pullback_v1` 的 WFV 配置，判据① 用同机会集那条线），
  并明说 **① 的池化口径与 ④ 的逐折口径本页不出，而且本页跑的是单窗、不是 WFV** ——
  别拿面板的数字去声称过了 ①/④。
  ⚠️ 这条文案我**改了两次**：第一版把出处写成「`preset_defs/` 那条 preset 的 docstring 顶部」，
  那是**复述**；四条判据的预注册正文在 `research/family_search.py` 的模块 docstring
  （它写着"写在这里意味着跑之前就定死"），协议/网格/折窗的预注册声明在 `research/wfv_search.py`。
  两处都是**查过**才改的（`family_search.py:1-10`、`wfv_search.py:1-40`），不是凭印象。
  另外三件交付前置一并列出（NAME 与文件名一致 / `n_comparisons` 的累加先例 / 行为锁基线）。
  顺带一条护栏：静态标记里的文案不许出现 markdown 的**反引号**（写这条时我手滑用了 `` ` ``，
  页面上的代码一律是 `<code>`）—— 实测静态部分反引号 0 个，所以这条锁是空的、不会误报。
- **台账「回填这一行」只回填了半个配置**（第四轮撞出来的，是一个**静默**缺陷而不是缺按钮）：
  台账那一行的窗口是可点的，点了会把卡片的**日期**填成那一对 —— 但族卡片上真正决定跑出来
  是什么的，是那几个**参数下拉**（默认 = 网格中点）。于是"复现某一次"实际上复现不了：
  用户点完回填、点「回测」，跑的是**另一个配置**，而提示写着"已填入上次的窗口"，看起来像复现；
  更糟的是那次新跑会**进台账、推高 k**（付了一次钱，拿到的不是想复现的那次）。
  这也让台账的 Δ 列（"同配置重跑应当差 0"）对族型运行根本用不了 —— 同配置复现不出来。
  现在点那一行会把**窗口 + 族参数**一起回填：取值只在**预注册网格**上匹配，不在网格上的
  **逐项报出来**（"那一行用的是另一个网格"），不静默取近似；preset 行照旧只填窗口，
  并说明"参数由定义体决定，页面上改不了"；早于 `job_id` 字段的旧行退化成只填窗口，也说明。
  验证：node 里对 `applyRunConfig` 断言（网格上的值真的写进下拉 / 不在网格上的**不覆盖现值**且
  逐个报出 / preset 行不误报 skipped），浏览器里先改乱三个参数再点那一行，实测三项全部回到
  那一行的取值。顺带把 DOM 桩改成**按 id 缓存元素** —— 浏览器里 `$(id)` 每次拿回的是同一个对象，
  桩不缓存就没法断言"写进去的值"（原来每个 id 都返回新对象，等于假设"写入即丢弃"）。
- **刷新后找回的面板印着另一套命令**（第五轮，与上面那条同一个病根：**面板上的命令是拿卡片
  当前输入现拼的**）：`cliCmd` 直接读卡片上的窗口输入框 / 族参数下拉 / 运气对照勾选框 / 备注框 ——
  这对卡片上的「复制命令」是对的（用户接下来要跑什么），但面板上那句「完整命令」描述的是
  **已经在跑的那个任务**。页面一刷新，卡片输入回到默认值，于是找回的面板印出一条
  **像是这次任务、其实是另一套配置**的命令；标题里的参数与运气对照更是直接没有（`/api/jobs`
  当时只发 id/kind/strategy/window）。刷新后想复制命令复现它的人会被带到别处，而且不报错。
  改：命令的构造抽成 `cliCmdFor(kind, id, lo, hi, params, controlRuns, note)`（输入全部由调用方给），
  `cliCmd` 只是"用卡片当前输入调它"这一种用法；`panel()` 多一个可选的 `cmd` 参数；
  `/api/jobs` 补发 `params` / `control_runs` / `note`；`recoverInflight` 用**服务端那份请求**重建标题与命令。
  验证：浏览器里带参数 + 运气对照 + 备注提交一次，**运行中刷新页面** —— 卡片已回默认值
  （参数 4 / 窗口 2024-04-09 / 勾选框未勾），而找回的面板仍写着提交时的 6/3/0.4、
  2025-06-02..2025-10-13、运气对照 200 次，命令里的参数指纹与提交时**同一个**。
- **「一笔都没成交」被涂成了成绩**（第六轮，实测出来的）：一段窗口里信号 0 个、成交 0 笔时，
  面板给出一整排 0 —— 收益 0、回撤 0、**曝光匹配超额精确为 0**（"零敞口 ⇒ 超额为 0"是本仓库的
  不变量）。数字本身没错，错的是**着色**：面板按符号上色 ⇒ 0 落在 `>= 0` 一侧涂成绿色
  （真数据上实测那一位是 −5.1e-15，于是涂成红色），读起来像"与池子打平"，实际是"根本没参与"；
  而 0 回撤（没持仓）也被涂成"差"的那一档。三处改动，都不碰任何数值口径：
  ① 0 笔时数字一律中性着色（`zc()`），并在数字上方加一句说清「0 是没参与而不是不赚不亏」；
  ② 判词草稿也带上这句 —— 草稿是直接粘进 VERDICT 的，写在页面上没用；
  ③ **显示上的 0 不带负号**：`−0.00pp` 不是数字，是浮点残差经 `toFixed` 之后的符号
  （|x| 小于半个显示单位，本来也印不出非零）。这条改在 `pct/pp/num` 三个格式化函数里，
  所以台账与对比视图里的同一个毛刺一起消失。真有值的一位小数不受影响（有断言钉住）。
  验证：合成市场上找到一段 0 笔的窗口（信号 0 个）并写成测试，钉住 n_trades=0、exposure=0、
  |超额| < 1e-9、`excess_per_exposure` 为 None（不是 NaN / 不是 0）、步骤里看得见"0 个候选 / 0 笔"、
  0 笔运行的接口 JSON 里没有裸 NaN；真数据上再跑一次同性质的窗口，浏览器里逐格核对
  着色与 `0.00pp`。
- **「跑过任意一条后显示」在新标签页里是假话**（第七轮）：池子的可评估范围只在内存与
  `sessionStorage`（本次会话）里 ⇒ 新开一个标签页就没有它，而卡片上仍印着
  「（池子可评估范围：跑过任意一条后显示）」—— 台账里明明跑过很多次。范围落进台账
  （每次运行的窗口体检已经算过它），页面在台账里取回最近一条带该字段的行；
  范围是**池子**的属性（各 preset/族共用同一套 `DEFAULT_SPEC`），所以任意一条旧运行都成立。
  验证：真数据上跑一次 → **新开标签页**（sessionStorage 空）→ 卡片上直接显示
  `2024-04-10 .. 2026-10-16`，并写回本会话。

## 三、补的护栏（每一类都对应一次真踩过的坑）

- **执行级护栏**：把内联脚本装进最小 DOM 桩、在 node 里**真的执行**并调用黄金路径上的纯函数。
  TDZ 那类运行期错误语法检查看不见，字符串断言也看不见 —— 它抓的就是那次 blocking 回归
  （注入验证过它会红）。**注意：CI 上没有 node，这条护栏只在开发机生效**（与"真数据行为锁在
  没有本地库时跳过"是同一种诚实边界）。
- **数值/存在性护栏**：锚点偏移断言**量**而不是"含这个词"；每张图/表的新增能力进清单；
  代码地图里的路径要能 `import`/存在（这条今天真抓住一次：我在地图里写了 `<code>family_search.py</code>`，
  它不是仓库相对路径）。
- **"可见文案里混进标记"一族**（自己反复踩，所以按形态分开锁）：`**`（含 JS 模板串）、
  静态标记里的反引号、`title="..."` 里的 HTML 标签（属性值里的 `<b>` 不是加粗，就是那三个字符）、
  `METRIC_HELP` 走 `esc()` 所以更严。共同的判据是"**读者眼睛会看到的那一层**"，不是"代码里有没有"。
- **数字的显示形态**：显示上的 0 不带负号（`−0.00pp` 是浮点残差的符号，不是数字）——
  同时钉住"真有值的小数不许被抹掉"（−1.23pp 照旧）。

| 台账里一行坏 JSON | 接口不崩，但**静默少记** ⇒ 已改为计数 + 警告 |
| 窗口恰好 5 个交易日（下限） | 正常跑完，未被下限误伤 |
| 窗口整段落在指标预热期内 | 正常产出 0 笔的报告（selfcheck 通过） |
| `results/` 只读 | 原先裸 `PermissionError` ⇒ 已改为可行动文案 |
| 窗口伸到池子覆盖之外 | **曝光匹配超额静默失真** ⇒ 已修 + 披露 |
| 台账 40 行（表只显示 30） | 计数/筛选/Δ 口径都对；**但第 31 条在界面上够不到** ⇒ 已加「载入全部」 |
| 报告 60 份（接口上限 50） | 接口发了 total，**页面没显示** ⇒ 已显示 |
| 并发 3 个 + 取消中间那个 | 设计正确：被取消的那次不进台账、队列跳过它 |
| 报告文件被删（链接变陈旧） | 原先回一坨 JSON ⇒ 已改为人话页面 |

## 五、三条**开放项**：它们是研究口径的决定，不是 UX 缺陷

1. **命令行迭代不进 k**：平台运行会写台账、推高 k；命令行跑的不会（`family_search` 自带 k 记账，
   其余靠调用方声明）。页面把这件事写在命令行入口清单里（明说的不对称），**没有**让平台替命令行
   记账 —— 那等于猜调用方试了几组。
2. **权威 holdout 台账里的登记**：平台的越界运行（窗口跨进 holdout）一条都没以 `claim` 身份登记进
   `holdout_ledger.jsonl`；页面已把这本账的状态并排显示。要不要让平台在越界时**强制**登记
   （或拒绝越界窗口），是要动研究规矩的决定。
3. **裁过窗口的口径**：窗口伸到池子覆盖之外时，超额只比较共同覆盖的那一段（已披露）。
   零敞口 ⇒ 超额恰好 0 在**裁过与未裁两种情况下都成立**（实测），未裁窗口的数值逐位不变。

## 六、诚实边界：这一层**没有**验过的

- **触屏/窄屏的真实交互**：只验过静态布局（多档宽度下无横向溢出），没在真机上走过手势。
- **真实读屏器**：只用了可访问性树 + 键盘走查，没有用 NVDA/VoiceOver 实听。
- **报告里成百张 SVG 的读屏替代**：数值事实都在卡片的文字标签里（可读），但**图形本身**
  （K 线形态、均线关系）无法用文字替代 —— 这是这类报告的结构性限制，不是可修的缺陷。
- **CI 覆盖率**：执行级护栏与真数据行为锁在 CI 上会跳过（分别因为没 node、没本地库）。

## 六之二、明确**不做**的（附理由与测量）

- **浅色主题 / 跟随系统 `prefers-color-scheme`**。这不是按钮/导航缺口，而是一次**主题化改造**，
  而且成本是可量的：平台 CSS 里**写死的颜色有 27 种、分布在 42 处**（只有 11 个进了 `:root` 变量，
  `var()` 用 50 次）。要做就得先做一遍"颜色全部收敛到 token"的清扫 —— 否则会得到一个**半转换**
  的主题（输入框、代码块、警示框、卡片底色分属不同层，漏一处就是深底浅字的拼接）。对一个本机
  单人工具、且作者本就选了深色而言，这个代价大于收益。**报告侧不需要这条**：它的 `@media print`
  已经给了一套浅色，打印/另存 PDF 走那条路。
- **内联 favicon（已做）**：此前每次加载都有一次 `/favicon.ico` 的 404，打开 devtools 的人会以为
  有东西坏了。改成一个 data URI 的内联图标 —— 不产生任何外部请求，页面仍自包含。实测：当前加载
  不再产生任何 console 条目。
- **不引入前端框架/构建步骤**（既有决策，这里重申）：平台与报告都靠 stdlib + 原生 DOM；
  报告还必须保持**零脚本、零外链**（`html_report.selfcheck` 强制），这一条不能为了"顺手"而破。

## 七、怎么推翻"这一层已经齐备"

以下每条都可独立执行，任一条翻车就说明我的结论错了：

1. **随机抽一条入口**（按钮/链接/命令），真跑一遍，并把结果与**四个面**对照：页面 DOM、
   `/api/*` 的 JSON、盘上产物、CLI 打印 —— 任一处数字/说法不同即是缺陷。
2. **造边界**：把台账造到 40 行以上、报告造到 50 份以上、窗口造到池子覆盖之外、
   把 `results/` 设成只读、在台账里塞一行坏 JSON —— 逐个走一遍，看界面是否**如实**说明。
3. **只用键盘**走完：选策略 → 设窗口 → 跑 → 读结果 → 报告里筛出场原因 → 回平台。
   凡是"焦点看不见落在哪"或"某个动作键盘够不到"即是缺陷。
4. **刷新页面/换新标签页**在运行中途；**同时提三个任务**并取消中间那个。
5. **改一处代码，看那条执行级护栏是否变红**（它若抓不到，说明护栏本身是空的）。
6. **核对口径的一处两写**：`rg -n "HOLDOUT|2026-10-13" --glob '!*.pyc'`，逐个判断是"出处"
   还是"副本"；副本越多，漂移风险越大。
